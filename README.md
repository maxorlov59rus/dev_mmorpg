# Чёрная Материя (Black Matter) — MMORPG

Тёмное фэнтези-MMORPG: сервер на C++20, клиент на Unity, контент в MySQL-скриптах.

Репозиторий: <https://github.com/maxorlov59rus/dev_mmorpg>

> **Статус: ранний прототип.** Есть структура проектов, схема БД на 225 таблиц и 106 клиентских скриптов,
> но серверный цикл игры пока не реализован (см. [Текущее состояние](#текущее-состояние)).
> Всё игровое ядро — каркас.

## Архитектура

| Компонент | Технологии | Назначение |
|---|---|---|
| `dm-authserver` | C++20, OpenSSL, SRP | Аутентификация (TCP :8091) |
| `dm_server` (world) | C++20, MySQL, KCP, Lua | Игровой мир (UDP :8093) |
| `UnityClient` | Unity, C#, KCP | Клиент |
| `sql/` | MySQL | Схема и контент |
| `proto/opcodes.defs` | DSL | Единый источник определений протокола |

Сетевая модель: KCP поверх UDP для игрового мира, TCP для авторизации. Опкоды описаны в
`proto/opcodes.defs` (455 строк) и должны синхронизироваться между сервером и клиентом.

### Игровые системы в `dm-server/src/game/`

Кампании, заражение, фракции, репутация, гильдии и гильдейские войны, PvP (включая AutoPvP и Spirit Battle),
квесты (спроектированы по диапазонам уровней 1–5, 6–15, 16–26, 27–50, 50–60), крафт, аукцион, торговля, вендоры,
предметы и экипировка, подземелья и LFG-матчмейкинг, дом, зодиак, зачарование, достижения, события
(сезонные, туманная аномалия), погода, целостность файлов, чат, социальные связи, дуэли, воскрешение, прогрессия.

## Требования

- **Сервер:** Windows + Visual Studio 2022/2026 (или MSVC Build Tools) либо Linux с GCC/Clang; CMake ≥ 3.16;
  компилятор с поддержкой C++20; OpenSSL (сборка OpenSSL-Win64 — путь в `CMakeLists.txt` нужно поправить под
  свою установку); MySQL client library.
- **Клиент:** Unity Hub + редактор, совместимый с версией проекта (`UnityClient/ProjectSettings/ProjectVersion.txt`).
- **Данные:** MySQL 8.x.

## Сборка сервера

```powershell
cmake -S dm-server -B dm-server/build
cmake --build dm-server/build --config Debug
```

Результат: `dm-server/build/Debug/dm_server.exe` и `dm_authserver.exe`.

Запуск world-сервера:

```powershell
.\dm-server\build\Debug\dm_server.exe ..\dm-server\config\worldserver.conf
```

Конфиг можно не указывать — сервер ищет `config/worldserver.conf` относительно рабочего каталога и
каталога исполняемого файла.

## База данных

Создание схемы:

```bash
python tools/db_setup.py          # параметры подключения — в dm-server/config/worldserver.conf
```

Файлы в `sql/` делятся на базовую схему (`01_dm_auth.sql`, `02_dm_characters.sql`, `03_dm_world.sql`,
`04_dm_items.sql`, `06_world_map.sql`) и тематические подсистемы; `sql/upgrades/` — инкрементальные патчи.

## Клиент Unity

1. Установить Unity через Hub (версия — из `UnityClient/ProjectSettings/ProjectVersion.txt`).
2. Открыть папку `UnityClient` как проект.
3. Сетевые параметры — в `MMONetworkClient` (`ipAddress`, `port`).

Холодный импорт проекта занимает заметное время: `Library/` в репозиторий не входит.

## Тесты

```bash
python tools/run_tests.py                    # все наборы
python tools/run_tests.py --suite data       # только контракты данных
python tools/run_tests.py --json report.json # отчёт в JSON
```

Наборы:
- **unit** — `ctest` в каталоге сборки сервера (пропускается, если не собрано);
- **data** — контракты данных: 1200 предметов, уникальность entry/displayid, сверка CSV ↔ SQL, синтаксис SQL;
- **protocol** — сверка `proto/opcodes.defs` с `EMMOOpcode.cs` и `MMOProtocol.h`, симметрия CMSG ↔ SMSG.

## Мир и лор

Полное описание вселенной — в [docs/01-Лор-и-фракции.md](docs/01-Лор-и-фракции.md) и
[docs/01-Lore-and-Factions.md](docs/01-Lore-and-Factions.md).

Три силы породил Раскол Первородного Кристалла: Свет (порядок), Тьма (энтропия) и Пустота.
Современная эпоха (год 501+) отмечена событием **Заражения**, угрожающим всем фракциям.

| Фракция | Тема | Столица |
|---|---|---|
| Орден Света | порядок, искупление | Ательгард |
| Тёмный Орден | власть, контроль | Умбра |
| Нейтральные | свобода, исследование | Грейвхейвен |

Кампании для уровней 70–99 закреплены за фракциями, мировые события (Заражение, Разрыв, Великая охота)
управляются состоянием мира и действиями игроков.

## Текущее состояние

Готово:
- схема БД — 225 таблиц, включая игровые предметы (1200 записей) и квестовый контент 1–60;
- серверные менеджеры игровых систем (большинство — каркас с API);
- клиентские виджеты UI (106 скриптов);
- формат протокола и набор опкодов;
- скрипты сборки, тестирования и CI.

Не готово / ограничения:
- `main.cpp` запускает echo-цикл UDP и не подключает игровую логику, БД и менеджеры;
- `Opcodes.h` и `MMOProtocol.h` содержат только `OPCODE_VENDOR_LIST` — генератор опкодов отсутствует;
- часть менеджеров не реализована (`Enhancement`, `GuildWar`, `Zodiac`, `Achievement`, `FactionWar`,
  `ChecksumCalculator`, `ServerMgr`);
- шесть файлов исключены из сборки (`VendorMgr`, `TradeMgr`, `QuestSystem_Level10`, `QuestGossipHandlers`,
  `LFGMgr`, `SmartAI`) — рядом лежат `.bak`-копии;
- путь к OpenSSL и порядок объявления цели `lua` в `CMakeLists.txt` требуют правки;
- транспорт и порт клиента (`TCP :7777`) не совпадают с сервером (`UDP :8093`);
- в git попали артефакты сборки и IDE (`.vs/`, `dm-server/build/`, DLL в `Binaries/`), а также
  `.bak`-файлы и собранный бинарник контрактного теста.

## Ближайшие задачи

1. Реализовать реальный серверный цикл: приём KCP/UDP → `PacketRouter` → хендлеры, инициализация БД и менеджеров.
2. Сгенерировать опкоды из `proto/opcodes.defs` и синхронизировать с клиентом.
3. Дописать пустые менеджеры, вернуть исключённые из сборки файлы.
4. Починить `CMakeLists.txt` (пути к зависимостям, порядок целей) и подключить `ctest` к CI.
5. Очистить индекс git от артефактов сборки и IDE.
