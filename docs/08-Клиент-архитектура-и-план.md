# Клиент «Чёрная Материя» — архитектура и план

Документ описывает клиентскую часть (`UnityClient/`): фактическое состояние, целевую архитектуру
и порядок работ. **Единственный источник истины по протоколу — `proto/opcodes.defs`.** Раздел может
расходиться с `docs/03-Сеть-и-протокол.md`, где описан несуществующий формат кадра (magic 0x444D,
HMAC/AES-GCM); фактический код использует 4-байтовый заголовок. `docs/03` требует синхронизации.

## 1. Текущее состояние

### Что есть
| Часть | Файлы | Состояние |
|---|---|---|
| Сеть | `Network/MMONetworkClient.cs`, `FMMOPacket.cs`, `KcpClient.cs`, `SRPAuth.cs` | TCP + поток-читатель; KCP — заглушка |
| Протокол | `EMMOOpcode.cs`, `Packets.cs` | ручной enum (80+) и только SMSG-структуры |
| UI | ~50 виджетов в `Assets/Scripts/UI/` | UGUI-подход через `public`-ссылки, 0 префабов |
| Разметка | `UI/Chat/Chat.uxml`, `UI/Campaigns/Campaign.uxml`, `UI/QuestLog/QuestLog.uxml` | 3 файла UI Toolkit, к C# не подключены |
| Сцена | `Assets/Project.unity` | одна сцена, сборка интерфейса в рантайме |
| Пакеты | `Assets/Packages/Kcp.2.7.0` (Kcp.dll, netstandard2.1) | загружен, не используется |

### Блокеры
1. **Проект не компилируется.** В 9 файлах используется тип `uint64` (нет в C#; нужен `ulong`), 22 места.
2. **Нет менеджеров.** `GameManager`, `ChatManager`, `CampaignManager` упоминаются в виджетах, но не существуют.
3. **`BinaryReaderExtensions.ReadBytes(int)`** вызывает сам себя — бесконечная рекурсия при обрезке строки.
   `ReadArray<T>` возвращает `default(T)`, то есть нули.
4. **Unity API из потока-читателя.** `MMONetworkClient.ReceiveLoop` вызывает `OnPacketReceived` в фоновом
   потоке; обработчики виджетов работают с `Transform`/`Text` — это падение или гонки.
5. **Расхождение протокола с сервером.** В `Opcodes.h` только `OPCODE_VENDOR_LIST`; в `defs` — 98 опкодов.
6. **Формат кадра только на клиенте.** Поля `magic/version/flags/sequence` из `docs/03` отсутствуют и в
   `FMMOPacket`, и в серверном `PacketFraming`.

## 2. Целевая архитектура

Пять слоёв, зависимости идут только вниз.

```
UI (UXML/UGUI)          ChatWidget, CampaignsWidget … — без сети и без данных
   ↓ события/команды
State (менеджеры)       GameManager, ChatManager, CampaignManager — в main-thread, работают с моделями
   ↓ вызовы
Protocol                Packets.g.cs (CMSG/SMSG), PacketRegistry, FMMOPacket (кадр)
   ↓ байты
Transport               ITransport: TcpTransport, KcpTransport, FakeTransport
```

Правила:
- UI не знает о `Socket`, `Thread`, `Kcp`. Только свойства менеджеров и события.
- Менеджеры не сериализуют сами — вызывают `PacketRegistry` и `Send(opcode, payload)`.
- Транспорт не знает игровых понятий — только `byte[]` и состояния соединения.

### Границы модулей

```
Assets/Scripts/
  Core/            AppBootstrap, IMainThread, ServiceLocator
  Transport/       ITransport, TcpTransport, KcpTransport, FakeTransport, LoopbackServer
  Protocol/        FMMOPacket, PacketRegistry, Generated/ (EMMOOpcode.g.cs, Packets.g.cs)
  State/           GameManager, ChatManager, CampaignManager, QuestManager, PlayerModel
  UI/              виджеты (переписать на UXML или UGUI-префабы)
  Generated/       только то, что выдаёт tools/proto-gen — править руками запрещено
```

### Транспорт

```csharp
public enum TransportState { Disconnected, Connecting, Connected, Failed }

public interface ITransport : IDisposable
{
    TransportState State { get; }
    event Action<TransportState> StateChanged;
    event Action<ushort, byte[]> PacketReceived;   // вызывается в главном потоке
    void Connect(string host, int port);
    void Send(ushort opcode, byte[] payload);
    void Pump();                                   // тик из Update
}
```

- **`TcpTransport`** — `System.Net.Sockets.Socket` в неблокирующем режиме или async `ReceiveAsync`;
  результат кладётся в `ConcurrentQueue`, разбор — в `Pump()` на главном потоке.
- **`KcpTransport`** — пакет `Kcp 2.7.0`; `KcpService.Update(now)` и обмен датаграммами выполняются в `Pump()`,
  без отдельного потока. Кадр `FMMOPacket` кладётся в один KCP-сегмент.
- **`FakeTransport`** — очередь в памяти, отвечает заранее заготовленными пакетами; нужен, чтобы запускать
  клиент без сервера и проходить UI-сценарии.
- Правило: **сетевой обработчик никогда не вызывает Unity API напрямую** — только через очередь и `Pump()`.

### Кадр

Действующий формат (совпадает с `dm-server/src/common/network/PacketFraming`):

```
offset size  поле
0      2     frame_size (u16, включает заголовок)
2      2     opcode (u16)
4      n     payload
```

`frame_size` ограничен 512 КиБ. Защита (HMAC, шифрование) вводится позже и только после того, как появится
на сервере — клиент не должен опережать сервер по протоколу.

### Состояние

- `GameManager` — синглтон-точка входа, владеет `ITransport`, `PacketRegistry`, моделями и менеджерами.
- Менеджеры публикуют события (`ChatManager.MessageReceived`, `QuestManager.QuestUpdated`), UI подписывается.
- Модели — чистые `class` без `MonoBehaviour`; это позволяет тестировать логику без сцены.

## 3. Генератор протокола

`tools/proto-gen` (план: Python 3 без внешних зависимостей, ~300 строк) читает `proto/opcodes.defs`:

- `@opcode NAME 0xNNNN chan=… dir=… { … }` → `EMMOOpcode.g.cs` (enum `ushort` с явными значениями)
  и `Packets.g.cs` (класс запроса с `Serialize()`, класс ответа с `Deserialize()`);
- типы `u8 u16 u32 u64 i32 i64 fp16 str<n> guid bytes arr<T>{max}` → соответствующие методы `BinaryWriter/Reader`;
- `guid` — `ulong` (на сервере `u32`, клиент читает 8 байт только если сервер так объявит; до решения
  серверной стороны используем `u32` с расширением до `ulong`).

Правила:
- `Generated/` в git хранится, но помечается «не редактировать»; расхождение с `defs` ловит тест.
- Проверка `tools/run_tests.py --suite protocol` уже сопоставляет `defs` с `EMMOOpcode.cs`; после перехода
  на генерацию она становится обязательной в CI и должна падать при расхождении.
- Ручные `EMMOOpcode.cs` и `Packets.cs` удаляются после переключения.

## 4. Этапы работ

### Этап 0. Компиляция (0,5–1 день)
1. `uint64` → `ulong` (22 места, 9 файлов).
2. Исправить `BinaryReaderExtensions` (рекурсия, `ReadArray`).
3. Заглушки `GameManager`, `ChatManager`, `CampaignManager` — минимальные, но дающие запуск сцены.

**Результат:** проект открывается и собирается в редакторе.

### Этап 1. Транспорт (2–3 дня)
1. `IMainThread` + очередь в `Update`, `PacketReceived` гарантированно в главном потоке.
2. `TcpTransport` на `Socket` с `Pump()`.
3. `FakeTransport` и сценарий «подключились → пришли 3 пакета → UI обновился».

**Результат:** клиент запускается без сервера, интерфейс получает данные.

### Этап 2. Генератор (2–3 дня)
1. `tools/proto-gen`, разбор `defs`, генерация `EMMOOpcode.g.cs` и `Packets.g.cs`.
2. Переключить транспорт и менеджеры на сгенерированные типы, удалить ручные.
3. Тест протокола в CI.

**Результат:** протокол больше не расходится с `defs` вручную.

### Этап 3. Первый вертикальный срез — чат (3–4 дня)
1. `ChatManager`: каналы `say/party/raid/guild/zone/whisper` (значения `u8` по `defs`), история на 50 сообщений.
2. `ChatWidget` на `UXML` (`Chat.uxml` уже есть) вместо виджетов с `public`-ссылками.
3. Локальный сервер `FakeTransport` → сообщения в обе стороны.

**Результат:** рабочая функция, которую можно проверить глазами.

### Этап 4. Вход и персонажи (1 неделя)
`CMSG_AUTH_*` (SRP), `CMSG_WORLD_HELLO`, `SMSG_CHAR_LIST`, `CMSG_CHAR_CREATE`, `CMSG_CHAR_SELECT`.

### Этап 5. Мир (после готовности серверного цикла)
`SMSG_SPAWN/DESPAWN/DELTA`, движение по KCP, AOI; UI: карта, журнал квестов, инвентарь.

## 5. Риски

| Риск | Влияние | Смягчение |
|---|---|---|
| Сервер отдаёт 1 опкод из 98 | клиент не пройдёт даже вход | сначала синхронизировать `Opcodes.h` с `defs` |
| `docs/03` противоречит коду | путаница в кадре и портах | считать источником `defs`; правки `docs/03` отдельной задачей |
| `guid` 4 vs 8 байт | сдвиг полей во всех пакетах | зафиксировать в `defs` как `u32`, расширять при необходимости |
| KCP в редакторе Unity (IL2CPP/Editor) | падение или нерабочий клиент | проверить на тестовом сокете до этапа 5, оставить `TcpTransport` как рабочий путь |
| `FakeTransport` даёт ложную уверенность | баги видны только на сервере | реплей записанных пакетов из `PacketCapture` |
| UI переписывается дважды | потеря времени | UXML сразу; новые виджеты — только на UXML |

## 6. Определения готовности

Этап считается закрытым, когда:
- проект собирается без ошибок и предупреждений компилятора;
- `tools/run_tests.py --suite protocol` зелёный;
- сцена запускается без `NullReferenceException`;
- `README` проекта клиента содержит актуальные порты, режим `FakeTransport` и команды запуска.

## 7. Открытые вопросы

1. Кто владеет протоколом: клиент подстраивается под сервер или наоборот? Предложение: `defs` → сервер и клиент.
2. `guid` — 32 или 64 бита? От этого зависит размер всех пакетов.
3. KCP — обязателен ли он для входа в мир, или достаточно TCP (упрощает первый этап).
4. UXML или UGUI как единый стандарт UI? Сейчас в проекте смешаны оба, и `Chat.uxml` не подключён.
