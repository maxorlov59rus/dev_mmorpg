# Сеть и протокол «Чёрная Материя»

## 1. Транспорт

| Канал | Транспорт | Порт | Назначение |
|---|---|---|---|
| Auth | TCP + TLS1.3 (mbedtls) | 8091 | SRP6a, устойчив к потерям, критичен к целостности |
| World | TCP + TLS1.3 | 8092 | сессии, чат, гильдии, квесты, лут-роллеры — всё «редкое, но важное» |
| Map | **UDP (KCP-фрейм)** поверх DTLS-like handshake (session key из world-канала) | 8093+ | движение, AOI-дельты, combat events — 20 Гц |
| HTTP API | HTTPS | 8443 | loginserver: биллинг, character CRUD, матчмейкинг, статус шардов |

Почему KCP, а не raw UDP/RakNet/UE-репликация: гарантированная доставка поверх UDP с
управляемым window/rtt — предсказуемая задержка на мобильных сетях (4G handover),
открытая реализация на C++ и Blueprint-доступная на клиенте, нет зависимости от UE replica system.

MTU-бюджет: ≤ 1150 байт на datagram (без IP fragmentation). Пакеты > budget режутся на
фрагменты на уровне фрейма (не KCP fragment, а наш `chunking`, чтобы дельта-стримы
не блокировали input-пакеты — priority queues: INPUT > EVENTS > STATE > MISC).

## 2. Фрейминг (общий для TCP-каналов)

```
offset size  поле
0      2      magic 0x444D ('DM')
2      1      version протокола (byte, negotiation в hello)
3      1      flags  (bit0 compressed(zstd-lite dict), bit1 encrypted payload nonce present)
4      2      opcode (см. таблицу)
6      4      sequence (monotonic per connection)
10     4      length payload
14     n      payload
       16     HMAC-SHA256 truncated (first 16 bytes) — после шифрования AES-256-GCM
```

Handshake (после SRP): выводятся `k_world_enc`, `k_world_mac` из SRP session key
(как в TRC RC4-пост-auth stage, но современный AEAD). Anti-replay: окно по sequence.

## 3. Оpcodes (фрагмент; полная таблица генерируется из proto/opcodes.defs)

Нумерация как в TRC: `CMSG_*` клиент→сервер, `SMSG_*` сервер→клиент, диапазон по каналам:
world 0x0001–0x0FFF, map 0x1000–0x1FFF.

```
; --- auth (TCP 8091) ---
CMSG_AUTH_CHALLENGE        0x0001  {account_email}
SMSG_AUTH_CHALLENGE        0x0002  {salt_B, pubkey_gN}
CMSG_AUTH_PROOF            0x0003  {A, M1}
SMSG_AUTH_RESULT           0x0004  {M2, realm_ticket}

; --- world (TCP 8092) ---
CMSG_WORLD_HELLO           0x0010  {ticket, client_build, platform(PC|ANDROID), device_id}
SMSG_CHAR_LIST             0x0011  {[guid,name,faction,class,level,zone]}
CMSG_CHAR_CREATE           0x0012  {name,class,faction_start?}
CMSG_CHAR_SELECT           0x0014  {guid}
SMSG_MAP_ASSIGN            0x0015  {ip,port,map_session_key,reconnect_token}
CMSG_CHAT_SEND             0x0020  {channel,target,text}
SMSG_CHAT_RECV             0x0021
CMSG_GUILD_*               0x0030..0x003F
CMSG_QUEST_ACCEPT/COMPLETE 0x0040/0x0041
SMSG_QUEST_UPDATE          0x0042
CMSG_AUCTION_LIST/BID      0x0050/0x0051
CMSG_MAIL_*                0x0060..
SMSG_FACTION_STATE         0x0070  {frontline control, seepage list, season timer}
CMSG_CORRUPTION_QUERY      0x0071
SMSG_SEASON_END            0x0072

; --- map (UDP/KCP 0x1000+) ---
CMSG_MOVE_TICK             0x1001  {seq,time,ticks:[{dx,dy,dz,dir,flags}]} ; delta-compressed
SMSG_SNAPSHOT              0x1010  {full state of visible entities}        ; при входе/AOI change
SMSG_DELTA                 0x1011  {entity updates since last ack seq}
CMSG_AOI_ACK               0x1012  {last_seq}                              ; server держит ring buffer
CMSG_CAST                  0x1020  {spell_id, targets[], src_pos}
SMSG_CAST_START            0x1021 / SMSG_CAST_RESULT 0x1022 {effect mask, dmg fixed-point}
CMSG_INTERACT              0x1030  {guid,type,payload}
SMSG_SPAWN                 0x1040 / SMSG_DESPAWN 0x1041
SMSG_COMBAT_LOG            0x1050
CMSG_PING / SMSG_PONG      0x10FF  {client_time} / {client_time, server_time} ; clock sync
```

## 4. Модель репликации

### 4.1 Server-authoritative movement
Клиент шлёт `CMSG_MOVE_TICK` 30 Гц (batch до 3 sub-tick'ов по ~10 мс каждый). Сервер:
1. проверяет скорость: `|Δpos| ≤ max_speed*dt*(1+ε)` + navmesh raycast (walkable);
2. применяет движение (учитывая knockback/slow от auras);
3. если рассогласование > 25 см — `SMSG_MOVE_CORRECT` (hard correction) либо soft lerp.

Клиент: prediction своего персонажа + reconciliation (буфер последних 1 с инпутов,
переигрывание от ack'd server state — стандартная модель Valve/TRC-подобных MMO).
Чужие персонажи/NPC: интерполяция между снапшотами с буфером 100–150 мс
(на Android — adaptive interp: при jitter > 40 мс буфер растёт до 250 мс).

### 4.2 AOI (area of interest)
Серверный grid 128×128 м (совпадает со стриминг-секторами UE). Правила видимости:
- радиус интереса: PC 200 м, Android 120 м (конфиг клиента влияет на подписку через
  `CMSG_SET_INTEREST {radius, detail_tier}` — экономия трафика mobile);
- приоритеты сущностей: raid-target > hostile-casting > group-member > other;
- hard cap объектов в подписке: 300 (soft) / 400 (hard) — перешагнувшие получают
  LOD-level «impostor» (статичная позиция раз в 2 с).

Дельты: `SMSG_DELTA` содержит bitmask изменённых полей на entity (pos/rot/anim-state/
hp/mana/auras-crc/vitals). Position quantized: int16 relative to cell origin (0.5 см шаг).
Анимация: не bones, а `anim_state(u16) + phase(fixed u8)` — клиент сам маппит на UE AnimBP.

### 4.3 Полоса пропускания (бюджет на игрока, боёвка 40 человек рядом)
```
вход:   move ticks 30 Hz × ~24 B ≈ 0.7 kbps
выход:  delta 20 Hz × (avg 30 entities × 18 B) ≈ 86 kbps + события ≈ 110 kbps
итого:  ~120 kbps Android / ~180 kbps PC (радиус больше) — приемлемо для 4G.
```

## 5. Безопасность и античит (сетевой слой)

- Всё состояние — на сервере; клиент физически не может знать лут до `SMSG_LOOT_STATE`.
- Rate limiting per-session (Redis token bucket): packets/sec, casts/sec, trades/min.
- Server-side sanity: impossible travel (geo-ip vs last map position), teleport abuse,
  speed variance detection → авто-флаг в Kafka для обзора ГМ + auto-ban rules (dm_auth).
- Crypto: TLS для TCP, AES-GCM+HMAC для KCP-фреймов, nonce из sequence; ключи живут
  до re-auth (max 24 ч).
- Client integrity: build-hash check в `CMSG_WORLD_HELLO`; signature-attest Android
  (Play Integrity API) / Steam owner-check PC → уровень доверия аккаунта.

## 6. Reconnect и отказоустойчивость

Обрыв map-канала: клиент мгновенно шлёт `CMSG_RECONNECT {map_session_key, last_seq}`
на тот же mapserver (он держит сессию 60 с) → `SMSG_SNAPSHOT` от last_ack → resume.
Если mapserver недоступен — worldserver назначает новый (state rebuild из БД-snapshot).
World-канал важнее: его потеря = logout flow. Heartbeat: ping 5 с, timeout 15 с.

## 7. Версионирование протокола

`version` byte в заголовке + семантика только additive: удалённые opcodes уходят в
deprecated range (0x0F00). CI-тест: golden-packet fixtures (proto/tests/*.bin) сверяются
между серверным генератором и клиентским парсером (UE C++) — защита от drift.
