# Клиент на Unreal Engine 5.8 — структура и кроссплатформенность

## 1. Структура проекта UE5.8

```
DMClient/                       # Git LFS для ассетов; engine-версия пинится (5.8.x)
├── DarkMatter.uproject
├── Config/
│   ├── DefaultEngine.ini       # streaming, r.*, net off (UE replication не используется)
│   ├── DefaultGame.ini
│   ├── Windows/WindowsEngine.ini
│   └── Android/AndroidEngine.ini, AndroidScalability*.ini  # Low/Medium/High/Epic пресеты
├── Content/
│   ├── Maps/                   # один Persistent Level на регион + World Partition
│   │   ├── AurilianMarch/      # стартовая зона Рассвета
│   │   ├── MulKeshar/          # стартовая Круга
│   │   ├── TarUnem/            # портовый город Порога
│   │   └── Instances/…         # инстансы (без WP, lightmaps baked offline)
│   ├── Characters/             # скелеты, AnimBP, MetaHuman-лицо только PC preset
│   ├── Fx/                     # Niagara: «Материя» VDF shader (дешёвая mobile-версия)
│   ├── UI/                     # CommonUI widgets (см. §4)
│   └── Data/                   # DataTable-зеркала dbc (Item.dbc → UDataTable via tool)
├── Source/DarkMatter/
│   ├── DMRuntime/              # игровой модуль
│   │   ├── Net/                # DMNetDriver: KCP client, фрейминг, парсер SMSG_DELTA
│   │   │   ├── Crypto/         # mbedtls static lib, SRP client
│   │   │   ├── Kcp/            # порт ikcp.c под UE platform sockets
│   │   │   └── Predict/        # movement prediction/reconciliation (FixedPoint!)
│   │   ├── World/              # EntitySubsystem (pool), AOIDirector, ActorMixer
│   │   ├── Combat/             # визуальный слой спеллов (получает события от сервера)
│   │   ├── CorruptionFx/       # post-process деформация по Corruption %
│   │   └── Platform/           # абстракция input/save/purchase (PC|Android)
│   ├── DMLauncher/             # экран логина/патча/выбора шарда (Slate, до загрузки мира)
│   └── DMEditor/               # tool-скрипты редактора (экспорт коллизии для mapextractor)
├── Plugins/
│   ├── DMAssetPipeline/        # cook-правила, manifest-генерация паков
│   └── PlayIntegrity/          # Android attestation
└── Build/                      # CI артефакты (не в git)
```

Ключевое решение (ADR-005): **UE replication выключена** (`bUseReplication=false` для
всех actor'ов; мир собирается из пула `AEntityActor`, которых спавнит/двигает наш
`EntitySubsystem` по данным с mapserver'а). Плюс: полный контроль трафика, минус: сами
пишем интерполяцию (готово, docs/03 §4).

## 2. Пайплайн контента «UE ↔ сервер»

```
Художник/дизайнер (UE Editor)
   │  Level Instance / WP cell
   ├──► mapextractor (tool): collision blobs + navmesh (Recast) → dm_world.maps blob
   ├──► DMAssetPipeline: cook → pak chunks (по 25 МБ) → CDN manifest.json {hash,size,platform}
   └──► DataTable export → CSV → sql/dbc_import → Item.dbc etc. (тот же источник!)
```
Один источник истины для характеристик предмета = DataTable в редакторе → экспорт и в
клиентский pak, и в серверный dbc. Несовпадение версий блокируется build-hash в hello.

### 2.1 Стартовый контент lvl 1–5: диалоги, дроп, служебные NPC (v3)

Источник истины — `sql/upgrades/StarterContent_L1_5.sql` (+ StarterQuests.sql,
NPC_Config.sql). Двусторонний контракт:

| Данные | Сервер (runtime) | Клиент (pak/DataTable) | Wire |
|---|---|---|---|
| Диалоги мобов/NPC (`broadcast_text` 90xxx–92xxx) | SmartAI: Aggro/Wound/DeathTextID → `SMSG_CREATURE_TEXT` | `DT_BroadcastText` → UDialogueSubsystem (кэш text_id→FText) | 0x2014 |
| Gossip-меню (`gossip_menu(_option)` + `dm_conditions`) | GossipMgr фильтрует опции **до** отправки; replay-guard на SELECT | `DT_GossipOption` — только тексты/иконки, **без правил фильтрации** | 0x2010–0x2013 |
| Квесты lvl 1–5 (`quest_template` 1001–1007, `quest_chain`, `quest_poi`) | QuestMgr: accept/gates/progress/rewards | `DT_Quest`, `DT_QuestChain` (журнал, стрелки «продолжить у…», POI-маркеры) | 0x2000–0x2007 |
| Дроп по заданиям (`quest_drop_data`, `loot_template`, `reference_loot_template`, `zone_loot_rule`) | LootMgr::RollLoot после OnKillCredit | не нужен (результат приходит в лут-панели) | SMSG_LOOT_* |
| Служебные NPC (trainer/vendor/healer/banker/mailbox, entries 90020–90040) | script_name-обработчики gossip Action (TRAINER/VENDOR/HEALER/BANKER/MAILBOX) | `DT_Creature` (model/subname), `DT_Vendor` (витрины) | 0x2011/0x2013 action=1..5 |

Правила синхронизации:
* экспортёр `tools/dbc-export` читает таблицы по `client_dbc_export_map` (§6 SQL-файла)
  и генерирует DataTable-профили `{ID:int32, Text:FText, VoiceCue:Name}` и т.д.;
* клиент **никогда** не получает скрытые ветки диалогов (renegade-only, rep_rank_min) —
  server-authoritative, см. docs/03 §7;
* новый квест/реплика добавляются одним SQL-скриптом + реэкспортом pak; код не трогаем
  (данные-driven, как в TrinityCore DBC-конвейере).

## 3. Кроссплатформенные матрицы фич

| Фича | PC | Android High | Android Medium/Low |
|---|---|---|---|
| Nanite | ✅ | ❌ (fallback mesh) | ❌ |
| Lumen | HW RT | Lumen raster | baked GI + SSGI-lite |
| Virtual Shadow Maps | ✅ | CSMM | clustered low-res |
| World Partition streaming | ✅ | ✅ ( smaller cells 64м ) | ✅ |
| Niagra VFX Density | 1.0 | 0.6 | 0.35 (quality scale) |
| AOI radius (net) | 200 м | 120 м | 90 м |
| FPS target | 60–120 | 60 | 30 |
| Audio | full mix | reduced stems | mono-ish low sample |

Реализация через Scalability groups + `PlatformCfg` subsystem (INI-driven), а не if-else
в коде фич. Тесты: automated perf-профили на device farm (Firebase Test Lab).

## 4. UI/UX: единый HUD для тача и клавиатуры

- **CommonUI** widget-стеки с активаторами: `PCInput` (keybinds, hover) vs `TouchInput`
  (radial ability wheel, авто-прицел «soft-target», крупные hit-areas ≥ 48 dp).
- Ability bar: 12 слотов PC / 2 ряда по 6 тач; drag-to-cast опция.
- Камера: орто-изометрия MMO (top-down 45°) — компромисс: одинаково читаема на 6" и 27",
  меньше motion sickness на тач-дрэгах, проще античит LOS.
- Настройки сохраняются на сервере (`characters.settings`) → кросс-платформенный перенос.

## 5. Патчинг клиента

- Launcher сравнивает локальный manifest с CDN; докачка diff-паков (chunk-based, как
  UE IoStore `zen` container per-platform). Target: патч игры ≤ 150 МБ typical.
- Google Play: AAB с asset-pack delivery для регионов (base APK < 150 МБ требование).
- Обязательное правило: протокол vN поддерживает клиентов vN и vN-1 (grace window 2 недели).

## 6. Производительность: чеклист Android

1. Загрузка: целевой cold-start до character select ≤ 12 c на SD778G (async loading,
   pre-cooked WPF streamables, minimal splash scene).
2. Память: бюджет RSS 2.2 ГБ — текстуры ASTC 4×4/6×6 mip-streaming, entity pool без GC
   spike (UObject min: акторы переиспользуются, анимации shared).
3. CPU game thread: тик логики клиента отделён от рендера; предсказание движения в
   worker thread (safe: fixed-point state lock-free ring buffer).
4. Battery/thermal: dynamic resolution 0.7–1.0, FPS cap по температуре (PowerHint API).
5. Сеть: adaptive interp buffer (docs/03), pause-reconnect при потере сессии ≤ 60 с
   без выхода в лобби.

## 7. Тестирование клиента

- GA (gameplay automation) сценарии: вход→квест→бой→смерть→резурект на headless-дроне.
- Net-emulator: прогон golden-packet fixtures (proto/tests) против клиентского парсера.
- Device matrix: top-20 SoC (Firebase Test Lab) + 2 budget (RAM 4 ГБ) еженедельно.
- Crash reporting: Breakpad/Sentry, symbol upload per-build (и серверные core-dumps).
