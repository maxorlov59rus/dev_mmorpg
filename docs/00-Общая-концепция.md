# Проект «ЧЁРНАЯ МАТЕРИЯ» (Dark Matter) — кроссплатформенная MMORPG

## 1. Резюме

MMORPG в тёмном фэнтези-сеттинге, ядро мифологии — **Чёрная Материя** (Тёмная Пустота,
«Материя До-Мира»), первородная субстанция, из которой сотворён мир и которая стремится
его поглотить. Игроки делятся на **фракции**, чьё отношение к Чёрной Материи определяет
геймплей, прогрессию, PvP-зоны и финальные эндгейм-события.

- **Движок клиента:** Unreal Engine 5.8 (Lumen/Nanite для ПК, scaled-пресеты для Android).
- **Платформы:** PC (Windows/Linux) + Android (touch-управление, облачные сейвы, кросс-прогрессия).
- **Сервер:** самописная распределённая архитектура **по аналогу TrinityCore**
  (Worldserver / Authserver / LoginServer / Mapserver-пул / БД MySQL+Redis).
- **Сеть:** собственное TCP/UDP-соединение с авторитетным сервером (сервер считает всё,
  клиент предсказывает и интерполирует).

## 2. Опорные цифры (целевые)

| Параметр | Значение |
|---|---|
| Игроков на шард (цель v1.0) | 8 000–15 000 онлайн |
| Игроков в одной локации (zone-cap) | 300 (soft), 400 (hard) → auto-phasing/instance |
| Тик мира (world tick) | 50 Гц (20 мс) логика, рассылка состояний 20 Гц |
| Задержка на клиенте (net interpolation buffer) | 100–150 мс |
| Android target | Snapdragon 7+/Dimensity 8000+, 30 FPS (60 опц.) |
| PC target | 60–120 FPS, Nanite/Lumen full |
| Размер пакета состояния (avg) | ≤ 90 байт на entity в delta-пакете |

## 4. Ключевые архитектурные решения (ADR-кратко)

1. **ADR-001. Сервер авторитетен полностью.** Клиент UE5 не владеет состоянием мира.
   Всё движение, урон, лут, торговля валидируется сервером. Клиент делает только
   client-side prediction + reconciliation (для своего персонажа) и интерполяцию остальных.
2. **ADR-002. Разделение Auth / World / Map как в TrinityCore.** Отдельные процессы:
   `dm-authserver`, `dm-worldserver`, `dm-mapserver` (горизонтально масштабируемый пул),
   `dm-loginserver` (HTTP/WS: биллинг, character select, матчмейкинг шардов).
3. **ADR-003. Одна карта = один mapserver-process** (в пределах capacity), внутри —
   многопоточный update loop по зонам interest. Переход между картами — handoff через
   worldserver (аналог `TransferRequest` TrinityCore).
4. **ADR-004. Данные контента — три слоя**, как в WoW/TRC:
   - статические таблицы (`dbc/`): предметы, спеллы, креатуры;
   - скрипты логики (`scripts/`: C++ compiled + Lua hot-patch);
   - живое состояние (`characters/`, `world/` БД).
5. **ADR-005. UE5.8 использует собственный net-слой НЕ для игры.** Replica system UE
   отключена; используется транспорт через выделенный сокет-модуль (libcurl/mbedtls +
   свой binary protocol), сериализация — компактный bit-packing, не UE NetSerialization.
   Причина: контроль полосы пропускания на Android и детерминизм серверной логики.
6. **ADR-006. Контент патчится раздельно:** клиентские паки (Pak/UFS) через CDN-манифест,
   серверные таблицы/Lua — без редкого рестарта worldserver (graceful reload).

## 5. Roadmap

| Этап | Длительность | Результат |
|---|---|---|
| M0 Прототип сети | 2 мес | auth→login→enter world→movement replication (PC console build) |
| M1 Вертикальный срез | +4 мес | 1 зона, 2 фракции, боевая система, инстанс-подземелье |
| M2 Android-порт | +3 мес | Touch UI, scalability-пресетЫ, актуальные устройства |
| M3 Фракционная война | +4 мес | Frontline-зоны, осады, Dark Matter corruption-механики |
| M4 Контент-наполнение | +6 мес | 3 стартовых региона, рейд 10p, крафт, рынок |
| M5 Closed Beta | +3 мес | Шардовая инфраструктура, ГМ-инструменты, античит |
| M6 Open Beta / Launch | — | Продакшн-кластер, биллинг, локализация |

## 6. Риски и меры

| Риск | Мера |
|---|---|
| UE5 на Android: память < 3 ГБ на бюджетных SoC | Nanite-off пресет, LOD-атласы, streaming-текстуры ASTC, целевой RSS ≤ 2.2 ГБ |
| Стоимость инженерии полного стека | Ядро = минимальный TRC-аналог; периферия (биллинг, матчмейкинг) на готовых SaaS до M5 |
| Читеры (speedhack, ESP) | Server-authoritative + movement validation + server-side AOI (клиент не видит то, что не в поле зрения) |
| Дисбаланс фракций | Dynamic faction balance: bonus-XP, миграционные квоты, cross-faction events |
| Hotfix-логика на C++ требует рестарта | Lua-обвязка для 80% геймплейных скриптов, C++ только для систем |
